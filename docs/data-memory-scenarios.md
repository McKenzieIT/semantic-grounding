## 2. 数据工程（E 类）

### E1｜主键唯一性实测 —— 纯 memory 的典型

- **场景**：接手 `dim_10000251_com_order_detail_info`，判断主键唯一性。
- **A 学到**：`ds=20260729` 单分区实测 **877 行 vs 873 个不同 `order_id`**，差额来自同一 `order_id` 重复 3 行、各自 `pay_amt`/`item_cnt` 不同。
- **今天落在哪**：直接写进表描述自由文本（语料原文：`(2026-07-30 实测 ds=20260729:877 行 vs 873 distinct order_id,差额 4 行源于同一 order_id 出现 3 行,各自 pay_amt/item_cnt 不同)`）—— **污染事实层**：复测一次就改定义指纹，ADR-0018/0019 漂移守卫误判为定义更新。
- **应该落哪层**：带日期的一次性实测数字 → **memory**；事实层只留结论「主键非唯一，真实粒度 (id, ds)」。
- **B 该做对**：做「订单金额按渠道聚合」时，不把 `COUNT(DISTINCT order_id)` 当订单数，也不按 `order_id` 关联导致行数膨胀。
- **晋升判据提示**：**永不晋升**——测量值随时间变化，是 observation 不是 property。

### E2｜实测做了一半，边界留 memory、结论进事实层

- **场景**：主键唯一性只在单分区上验过。
- **A 学到**：语料原文「`primary_key_unique` 基于 `ds=20250511` 分区实测（r=38=d），**未覆盖全分区**；跨分区可能存在历史快照重复」。同表 `confirmation.status` 停在 `draft`、`confirmed_by` 为 `dim-enrichment-2026-07-31`。
- **今天落在哪**：同 E1，自由文本。
- **应该落哪层**：**结论**（`primary_key_unique`）进事实层；**验证范围与残留风险**留 memory。
- **B 该做对**：知道该结论只在单分区上验过，跨分区使用前先补验。
- **晋升判据提示**：**部分晋升**——这是三层模型最细的一刀，#130 需裁「结论与其验证边界如何分家」。

### E3｜内部黑话 —— 该立刻晋升的 memory

- **场景**：业务方说「按 2 渠拆一下」，A 不知道 2 渠是什么。
- **A 学到**：`dws_10000251_acc_summary_df` 列注释里写着 `ch_type` =「渠道，又叫 **1渠**」、`ch_id` =「渠道id，又叫 **2渠**」。黑话只活在列注释里，`resolve_alias` 查不到。
- **今天落在哪**：列注释（读不到的地方）。
- **应该落哪层**：A 第一次被问住的过程 → memory；**别名本身 → 立刻晋升为事实**（确定性、可复用、无时效）。
- **B 该做对**：听到「2 渠」直接定位到 `ch_id`。
- **晋升判据提示**：**立即晋升**——晋升目标明确（alias），与 #126 的 `alias_hint → alias` 类型映射对上。

## 3. 数据分析（A 类）

### A1｜快照表跨日累加，重复计数

- **场景**：做趋势对比，直接对 `_df` 表跨 `ds` SUM。
- **A 学到**：语料里这条警告反复出现十余次——「`_df` 为日全量快照，跨 ds 直接 SUM 会重复累计角色×记录，趋势比较需固定单分区或用去重口径」；「`_di` 才是日增量」。
- **今天落在哪**：分散在十几张表的描述里，每张各写一遍。
- **应该落哪层**：A 踩坑过程与算错的那次数 → memory；`_df`/`_di` 的**粒度语义** → 本来就该是事实层（甚至该是概念层的命名约定，而非每张表重写一遍）。
- **B 该做对**：趋势对比自动固定单分区或走去重口径。
- **晋升判据提示**：这张卡暴露的是**事实层自身的重复**——同一条约定抄了十几份。#130 可借它讨论「命名约定类事实的归宿」。

### A2｜把推断当成事实写下来 —— 晋升规则的核心分界

- **场景**：判断 `dws_10000251_acc_summary_df` 的分析主体。
- **A 学到**：表描述原文「分析主体=账号（`user_type=2`，**由表名 acc 推断**；该表无 `user_type` 列，主体按账号汇总定义）」。这是**未经验证的推断**。
- **今天落在哪**：与真实字段说明并排躺在同一段自由文本里，读者**分不出哪句是实锤、哪句是猜的**。
- **应该落哪层**：带置信度与依据的推断 → memory；核实之后才进事实层。
- **B 该做对**：要么看到「这是推断、未核实」，要么看到「已核实、依据是 X」，不被蒙在鼓里。
- **晋升判据提示**：**这是晋升规则最核心的一条分界线**。#127 发现的三个休眠槽 `confirmation{status, confirmed_by, confirmed_at}` 正是为这种情况准备的，今天零消费者。

### A3｜「大R」没有阈值 —— 已验证查询的样本

- **场景**：业务方要「大R 留存」。
- **A 学到**：概念「付费经济」的 `alt_labels` 有 `大R`/`高付费`/`零氪`/`免费玩家`，但**全语料无一处定义「大R」是多少钱以上**。A 本次自选了口径。
- **今天落在哪**：口径只活在 A 的会话里，会话一关就没了。
- **应该落哪层**：本次采用的口径 + 为何这么选 → memory；被确认后晋升为**一等「已验证查询」**或指标定义。
- **B 该做对**：再算「大R 留存」拿到同一口径，两次数能对上。
- **晋升判据提示**：对应 #126 借鉴第 6 条——`{question, sql, verified_by, verified_at}` 作一等知识（Cortex VQR 形状）。

## 4. 数据治理 = ETL 运维（G′ 类）

> **采集发现**：k11 语料里 **ETL 运维类知识一条都没有**。搜「倾斜 / 产出 / 延迟 / 空分区」只命中游戏域的「资源产出」，无一条运维含义。
> 这比污染更能说明问题：工程与分析类经验**至少还能挤进表描述**（于是污染了事实层），而倾斜、产出、延迟**连挤都挤不进去**——它不属于任何一张表的「描述」，它是时点事件，今天在 SG 里**零落点**。

三张卡恰好构成时效性三级，是 #130 设计 memory 生命周期的核心素材。

### G1′｜数据倾斜 —— 可能长期有效，可晋升

- **场景**：按 `ch_id` 分组聚合 `dws_10000251_acc_summary_df`，任务卡在最后一个 reducer。
- **A 学到**：某渠道占 80% 行，是倾斜；改两阶段聚合后跑通。
- **应该落哪层**：倾斜观测（哪张表、哪一列、何时观察、占比）+ 绕过手法 → memory；若长期成立，「该表在 `ch_id` 上分布极偏」可晋升为表的稳定属性。
- **B 该做对**：写同类聚合时直接上两阶段聚合，不重踩。

### G2′｜产出时间与空分区 —— 稳定，可升为 SLA

- **场景**：早上查某 `dim_` 表，读到空分区，误判「没数据」。
- **A 学到**：该表每天固定时点才产出。
- **应该落哪层**：产出时间窗 + 某次具体延迟事件 → memory；稳定的产出时间可晋升为表的事实属性（SLA）。
- **B 该做对**：知道分区何时可用，不把空结果读成业务为零。

### G3′｜一次具体的未产出事故 —— 有失效时间，永不晋升

- **场景**：某天上游未产出或产出不全，当天指标偏低。
- **应该落哪层**：**带明确 `valid_from`/`valid_until` 的时点事实 → memory，永不晋升**（它不是任何定义的属性）。
- **B 该做对**：跨期对比时排除或标注那一天，不当成业务下跌。

## 5. 采集期间的额外发现（供 #130 / #131）

1. **「谁确认的」对不上**（#127 实测，321 表）：`confirmation.status` 分布为 draft 205 / analyst_confirmed 114 / business_confirmed 1 / unreviewed 1；而 `confirmed_by` 的 **319/321 是机器批次号**（`dim-enrichment-2026-07-31` 159、`enrichment-agent-2026-07-31` 134、`data-verification-agent` 26），唯一像人的只有 1 条 `user-2026-07-22-pay_type-semantics`。
   → **114 张表声称「分析师已确认」，确认人却填的是跑批 agent**，且服务端零消费者（无工具读它、校它、据此拦写）。
   → **对 #130 的直接影响**：如果晋升只是写一个 `confirmed_by`，它与现在这 114 张自称已确认的表没有区别。晋升必须有比「填个字段」更硬的东西。
2. **draft 占 64% 且不可发现**：205/321 停在 draft，而 `list_definitions` 只返回 `{id, kind, label, domains}`，**看不到确认状态**。「哪些表还没确认但被高频引用」今天无读面可答。
3. **域挂载无守门**：`getDanglingDomainRefs()` 存在但 MCP 从未调用；`domains` 的「加载时校验」实为建图副作用、**从不拒写**。k11 今天恰好 0 悬空（10 域对上 10 概念）是运气不是机制。
4. **卡片性质分两种**：E/A 类是「A 学到了什么」，G′ 类是「下一个人需要知道什么」。两者对读面的要求不同——前者可锚定到单个定义，后者常跨表、且带时间窗。#130 的存储形状须同时容得下这两种。

## 6. 接力剧本种子（Destination ④）

最小可跑剧本建议取 **E3 + A3 + G3′** 三张：

- **E3**：确定性晋升（别名），L0 层可断言 commit 与 trailer。
- **A3**：口径一致性，B 的答案必须与 A 的口径对上（L2 答案关键词）。
- **G3′**：时效性，B 在事故窗口内外的行为必须不同（唯一能证明「有效期」机制真的生效的卡）。

判定沿用 #129 的四级（L0 commit+trailer / L1 轨迹 / L2 答案关键词 / L3 跨宿主），N=5 取 ≥4/5；不入四门禁，走 opt-in `check-relay.ts`。
